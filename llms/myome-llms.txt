# MyOme

> MyOme is a CLIA-certified, CAP-accredited clinical laboratory in Menlo Park, California that
> sequences a patient's whole genome once and re-interprets it over time. It publishes a partner-facing
> REST API for ordering sequencing and analysis, tracking laboratory orders, and retrieving results.

Generated by API Evangelist from MyOme's published OpenAPI document and public website on 2026-08-26.
MyOme does not publish an llms.txt of its own (https://myome.com/llms.txt returned 404).

## API

- [MyOme API reference (RapiDoc)](https://api.myome.com/0/ui/): The published API reference. OpenAPI 3.0.2, info.version 2.51.0.
- [OpenAPI document](https://api.myome.com/0/openapi.json): 63 paths; operation detail is published for 8 of them to anonymous callers.
- Production base URL: https://api.myome.com/0/
- External sandbox base URL: https://api.sbx.myome.com/0/ (same document, for partner testing/development)

### What the API does

- List the sequencing and analysis **Products** available to the client (product ids are prefixed `PR`).
- Submit a **Requisition** for a sample (prefixed `RQ`). One **Order** (prefixed `OR`) is created per Product requested.
- Check requisition and order status through SUBMITTED -> AWAITING_SAMPLE -> ANALYZING -> CLINICIAN_REVIEW -> COMPLETED (also APPROVED, DENIED, CANCELED, FAILED, REFERRAL_LAB_LD_REVIEW).
- Retrieve **Reports** — sequencing data, structured interpretation data, and PDF reports.

### Publicly documented operations

- `GET /product` — list orderable products.
- `GET /consent` — list consent types; requires a `consents` query parameter.
- `GET /requisition` — list the caller's open requisitions (paginated with `page`/`per_page`, sortable).
- `POST /requisition` — create a requisition. Creates billable laboratory orders.
- `GET /requisition/{requisition_id}` — fetch one requisition.
- `GET /order/{order_id}` — order status and, when complete, result access.
- `POST /institutional/partner-requisition` — create a partner-scoped institutional requisition.
- `POST /institutional/campaign/{campaign_code}/individual` — enrol an individual into an institutional campaign.

### Authentication

Bearer JWT: `Authorization: Bearer <token>`. Tokens are issued by MyOme's Keycloak at auth.myome.com
using partner-specific credentials that MyOme sends by secure email at account creation. Tokens
refresh hourly. There is no self-service sign-up for API access.

### What an agent must know before calling

- **Writes are irreversible through the API.** `POST /requisition` orders a clinical genomic test
  against a patient sample. No cancel, void or refund operation is published, and no reversal window
  is stated anywhere. Escalate to support@myome.com rather than attempting a reversal.
- **There is no idempotency key.** A retried POST is a second billable test. Do not auto-retry writes.
- **There are no published rate limits** and no RateLimit/Retry-After headers, so there is no back-off signal.
- **Everything here is PHI.** Requests and responses carry identified patient names, dates of birth,
  addresses, contact details, family history and genomic findings under HIPAA.
- **The runtime error envelope is RFC 9457** (`application/problem+json` with type/title/detail/status),
  which differs from the `application/json` StructuredError envelope the spec declares.
